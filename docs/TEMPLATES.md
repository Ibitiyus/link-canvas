Это обычные проекты версии `1`, не отдельный урезанный формат. Все блоки, grid/free-размещение, слои, группы, фоны, анимации и размеры редактируются существующим Inspector. При создании экземпляра выдаются новые ID блокам, группам и пользовательским шрифтам с обновлением ссылок между ними. Сохранённая геометрия от размера экрана не меняется.

## Выбор и безопасная замена

Главная страница содержит ссылку в навигации, кнопку «Начать с шаблона» рядом с основным действием и отдельный раздел старта. В редакторе библиотека содержит «Шаблоны ↗» и «Сохранить как шаблон»; на телефоне они доступны через «Добавить» в существующей нижней панели.

- `/templates` — галерея, категории и локальная библиотека «Мои».
- `/templates/:id` — независимый предпросмотр без регистрации и без изменения текущего проекта.
- «Использовать» открывает подтверждение, предлагает скачать текущий JSON и объясняет последствия замены.
- Перед заменой сохраняется локальная копия исходной страницы вместе с локальными/облачными файлами. При ошибке загрузки медиа, записи копии или изменении страницы/аккаунта замена не выполняется.
- Просмотр галереи и шаблона не запускает автосохранение текущего проекта. Изменение дискового черновика другой вкладкой проверяется перед применением; повреждённый JSON также блокирует замену, а не сохраняется как демонстрационный fallback.
- После подтверждения открывается `/editor` с видимым полотном и закрытой мобильной панелью. Замена входит в Undo/Redo. На странице шаблонов доступно «Восстановить предыдущую страницу».

Резервная копия хранит **только последнюю заменённую страницу**. Для нескольких копий используйте собственные шаблоны или JSON. У авторизованного пользователя подтверждённая замена меняет активный облачный черновик через существующее автосохранение; опубликованный снимок обновляется только отдельной публикацией. Отмена не вызывает замену проекта.

## Свои шаблоны

«Сохранить как шаблон» создаёт именованную локальную копию. В «Мои» можно открыть её предпросмотр, повторно применить, переименовать и удалить с подтверждением. Удаление записи не удаляет текущий проект или публикацию.

Хранилище: отдельная IndexedDB `zin.templates.v1`, object store `templates`. Медиаданные копируются в существующую `link-canvas.files.v1`; приватные облачные файлы скачиваются при сохранении, поэтому локальная копия не зависит от сессии исходного владельца. В записи хранится стандартный Project, а не `blob:` URL. Внешние HTTP(S)-ссылки пользовательского проекта остаются ссылками.

Библиотека принадлежит браузеру и origin, а не аккаунту. Она не синхронизируется между устройствами и не публикуется. Очистка данных сайта удалит её; для переноса примените шаблон и экспортируйте обычный JSON с файлами. Лимит первой версии — 24 собственных шаблона плюс одна резервная копия, названия — 1–80 символов. Реальный объём ограничен квотой браузера. Неиспользуемые файлы автоматически не удаляются: они могут быть нужны текущему проекту или истории Undo.

## Медиа, публикация и производительность

Все встроенные изображения, GIF, видео и аудио созданы процедурно для ZIN без чужих фотографий, музыки или логотипов. Лицензия медиа — [CC0 1.0](../public/templates/LICENSE.md). Ссылки и QR ведут на `https://example.com` как явные демонстрационные значения: замените их своими.

Статические файлы находятся в `public/templates/v1/`. При применении загружаются только файлы выбранной композиции, проверяются их сигнатуры и они записываются в IndexedDB. Ответ HTML от SPA fallback не принимается как изображение или видео. При публикации файлы проходят обычную загрузку и копирование в Supabase Storage; публичная страница не зависит от исходного `/templates/v1/` или приватной сессии.

Встроенные карточки показывают PNG, снятые с реального Canvas Renderer, с `loading="lazy"` и `decoding="async"`. Галерея, определения композиций и диалог сохранения загружаются отдельными lazy chunks. Редактор не загружает библиотеку изображений при старте. Собственные карточки используют реальный Canvas, монтируемый только рядом с viewport, без анимаций и с `inert`, чтобы элементы плеера/ссылки в миниатюре не перехватывали управление.

Формат проекта, серверная схема, Supabase и Vercel не менялись. **Новая SQL-миграция для Stage 7 не нужна**; должны быть применены предыдущие миграции проекта до Stage 6 включительно.

## Разработка и воспроизведение медиа/превью

Обычный запуск: `npm ci`, затем `npm run dev`; откройте `/templates`.

Воспроизводимая генерация встроенных ресурсов (только для разработки, не для запуска приложения):

1. Python с Pillow и установленный ffmpeg: `python3 scripts/generate-template-assets.py`.
2. `npm run build`, затем `npm run preview` на порту 4173.
3. Chromium/Playwright: `node scripts/capture-templates.mjs`, затем `python3 scripts/resize-template-previews.py`.
4. `node scripts/capture-template-gallery.mjs` — обзорные скриншоты документации.

Готовые медиа и PNG уже включены в репозиторий. Python, Pillow и ffmpeg не требуются конечному пользователю или Vercel-сборке. Новых npm-зависимостей нет.

## Проверка после деплоя

1. Откройте главную на ПК и телефоне, перейдите в галерею, проверьте фильтры и превью каждого шаблона без входа.
2. В существующем проекте выберите другой шаблон, отмените замену и проверьте исходную страницу. Затем подтвердите, отредактируйте блок, перезагрузите и восстановите предыдущую страницу через галерею.
3. Для Music Artist проверьте аудио/видео, для Punk Zine — группу и свободное размещение, для Blank Canvas — отсутствие блоков.
4. Сохраните собственный шаблон, переименуйте, используйте повторно и удалите запись. Проверьте обычный экспорт/импорт JSON с файлами.
5. Войдите, сохраните в облако и опубликуйте. Откройте `/u/:username` в другом браузере: изображения, GIF, звук, видео, ссылки и эффекты должны работать.
6. Проверьте, что `/templates/v1/*.webp`, `.gif`, `.wav`, `.webm` и `/templates/previews/*.png` возвращают реальные файлы, а не `index.html`.
