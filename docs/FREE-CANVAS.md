# ZIN Stage 5: свободное полотно и группы

## Использование

У каждого из восьми типов блока в настройках есть «Режим размещения»: сетка или свободный. Переход в свободный режим сохраняет логический прямоугольник блока; обратный переход ищет свободные ячейки, не вытесняя закреплённые элементы. Сетка остаётся независимой от порядка слоёв. Старые блоки остаются сеточными, старый декор — свободным.

Свободный блок можно перемещать, менять за восемь маркеров, вращать отдельной ручкой, задавать X/Y, размеры и угол числом. «Сохранять пропорции» действует и на жесты, и на числовые размеры. На телефоне перемещение начинается после удержания; быстрый свайп прокручивает рабочую область. Области маркеров сохраняют 44 CSS px независимо от масштаба. Медиа взаимодействуют через существующий отдельный режим.

Выберите несколько элементов через Shift, флажки в слоях или кнопку множественного выбора над полотном. «Сгруппировать» переводит выбранные элементы в свободный режим без изменения их положения. После группировки режим множественного выбора выключается, чтобы сразу можно было двигать группу. Обычный выбор участника выбирает группу; кнопка отдельного редактирования в слоях/настройках позволяет менять конкретный элемент.

Группа поддерживает перемещение, пропорциональное изменение размеров, относительный поворот, закрепление, видимость, дублирование, переименование и порядок наложения. В слоях группа сворачивается. Команды порядка перемещают её как единое целое. Разгруппировка сохраняет текущие мировые координаты и свободное размещение. Завершённый жест — одна операция Undo. Копии создаются незакреплёнными.

## Совместимость и выпуск

Версия проекта остаётся `1`. Новые поля необязательны: у блока `layout`, `keepAspect`, `groupId`, у проекта `groups: [{id, name}]`. Старые данные не переписываются ради масштабирования. Метаданные проходят общий импорт/экспорт, localStorage, IndexedDB-файлы, облачный черновик и публичный снимок. Фоновая прозрачность, пользовательские шрифты и единое масштабирование полотна сохранены.

До выпуска frontend примените обычным процессом миграций, **без сброса базы**, в указанном порядке:

1. `202610210002_free_canvas_groups.sql` — серверная проверка новых полей и ссылок на группы.
2. `202610210003_free_canvas_validation_scope.sql` — однозначное обращение к параметру функции в проверке групп.

Применённые ранее миграции не изменены. Обе новые миграции проверены на локальном Supabase; production Supabase и Vercel в этой задаче не изменялись. Предшествующая миграция `202610210001_editor_layers.sql` также должна быть применена, если её ещё нет в окружении.

## Проверки

Выполнены реальные команды:

- `npm run typecheck`, `npm run build` — успешно.
- `npm test` — 112 модульных тестов.
- `TEST_PRODUCTION=1 npm run test:e2e -- --workers=1` — 61 прошёл, 3 сценария публичного маршрута пропущены в этом режиме; они выполняются следующей командой.
- `npm run test:canvas -- --workers=1` — 30 браузерных тестов, включая публичный маршрут с контролируемыми HTTP-ответами.
- `npm run test:cloud` — 52 интеграционные проверки настоящего локального Supabase.
- `npm run test:e2e:cloud` — 3 браузерных сценария с настоящими локальными Auth, Storage, черновиком и публикацией.

Браузерные наборы частично пересекаются, их количества не следует складывать как уникальные тесты. Проверены реальные bounding boxes редактора/предпросмотра/публичной страницы, touch на 320/390/768 px и просмотр до 1440 px, Grid/Free, поворот, resize, группы, история, JSON с восстановлением, reload, облачные метаданные, воспроизведение аудио/видео. Внешние медиа и публичный API в `test:canvas` контролируются тестовыми ответами; реальный Supabase проверяется отдельно.

## Ограничения

Группы одноуровневые, без вложенности. Масштаб группы равномерный, без skew и независимого растяжения по осям. После поворота рамка группы пересчитывается по мировым границам; числовое поле поворота группы задаёт дополнительный угол, а не хранит отдельный угол родителя. Дочерние элементы хранят мировые координаты. Размеры, шрифты и рамки сохраняют существующие допустимые пределы; недопустимое групповое преобразование целиком отклоняется с сообщением. Максимум 200 блоков и 100 групп.

Эмуляция Chromium touch и visualViewport не заменяет проверку настоящих Safari/iPhone, экранной клавиатуры и системных жестов. Production-публикация требует описанного выше применения миграций.

## Проверка после деплоя

1. Откройте старую опубликованную страницу на ПК и телефоне: композиция, фон, шрифты и прозрачность должны сохраниться.
2. В редакторе переключите текст и фото в свободный режим, переместите и поверните; верните один блок в сетку и проверьте отсутствие пересечений.
3. Выберите смешанные блоки, сгруппируйте, измените размер/угол, закрепите; проверьте выбор через слои, индивидуальное редактирование и Undo/Redo.
4. На телефоне проверьте удержание, обычную прокрутку, доступность маркеров, нижнюю панель и ввод с клавиатурой.
5. Экспортируйте JSON, перезагрузите редактор, восстановите копию. Затем сохраните облачный черновик и опубликуйте; сравните `/preview` и `/u/:username` на обоих устройствах, проверьте медиа и переход «Создать свой зин».
