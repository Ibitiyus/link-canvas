# Проверка этапа 3

Проверено 19 октября 2026 года в ветке `feat/stage-3-cloud-platform`, Node.js 24, Chromium `/usr/bin/chromium`. Сервер — настоящий локальный Supabase в Docker: PostgreSQL, Auth, Storage, REST, Edge Runtime и Mailpit. Рабочий удалённый проект не использовался.

| Проверка | Результат |
| --- | --- |
| `npm ci --cache /workspace/.npm-cache --no-audit --no-fund` | Зависимости воспроизводимо установлены из lock-файла. |
| `npm run typecheck` | Пройдено, ошибок TypeScript фронтенда нет. |
| `npm test` | **69 тестов, 10 файлов — пройдено.** |
| `npm run build` | Production-сборка создана. |
| `TEST_PRODUCTION=1 npm run test:e2e` | **33 прежних сценария — пройдено.** |
| `npm run test:cloud` | **36 проверок настоящего сервера — пройдено.** |
| `npm run test:e2e:cloud` | **3 комплексных сценария production-сборки — пройдено.** |
| Отдельный браузер без переменных Supabase | Добавление/редактирование блока, локальное сохранение и reload; объяснение недоступного облачного входа — пройдено. |
| Запущенный dev-сервер, `/editor` и `/src/main.tsx` | HTTP 200 после установки зависимостей и перезапуска сервера. |

Модульные проверки охватывают прежние сетку, геометрию, медиа, файлы, JSON и историю, а также очередь синхронизации, изменение во время загрузки, конфликт ревизий, остановку запроса при смене аккаунта, явное сохранение пустого проекта, независимость снимка от порядка JSON-ключей, username/возвратные маршруты и точную замену источников медиа без изменения ссылок/QR/текста.

Серверные проверки подтверждают реальные регистрацию/сессии/восстановление пароля, уникальность и резервирование username, RLS профилей и черновиков, запрет чужой записи и подделки публикации, CAS параллельных сохранений, проверку структуры проекта и опасных протоколов, недоступность серверных RPC пользователю, приватность и неизменяемость файлов, проверку сигнатур, запрет клиентской загрузки HTML в публичный bucket, отмену незавершённой публикации, чтение публичной версии без сессии, доступность байтов изображения и шрифта, независимость черновика, смену адреса, повторную публикацию, снятие и безопасную очистку.

Облачные браузерные сценарии проверяют перенос всех **8 типов блоков**, пользовательского WOFF2 и файлов с устройства. WAV размером **11 466 044 байт** загружается несколькими TUS-чанками. Отдельный анонимный браузер видит опубликованные блоки, загруженные изображения и шрифт, реально воспроизводит аудио и WebM; интерфейса редактора и локального проекта автора у него нет. Другой авторизованный браузер открывает приватный черновик и экспортирует JSON с облачными файлами. Проверены повторная публикация, старый/новый username, снятие, отмена замены существующего черновика без ложного сообщения об успехе, два конкурирующих устройства, offline/reconnect, выход и пустой новый аккаунт. Восстановление пароля проходит по настоящему письму **локального Mailpit**, с PKCE и входом по новому паролю.

Старые 33 сценария сохраняют покрытие перетаскивания/размеров/коллизий, слоёв и декора за границами, Undo/Redo, локального восстановления и повреждений/квоты, полного JSON, всех типов медиа и файлов больше 10 МБ, QR, пользовательских шрифтов, русского интерфейса, LAN без `crypto.randomUUID` и мобильного управления. Сторонние медиа в этих тестах контролируются фикстурами; воспроизведение реального YouTube этим не подтверждается.

SQL-миграция дополнительно применена заново после пересоздания пустой **тестовой** базы. Команда `cloud:reset` применила схему, но завершилась ошибкой healthcheck Storage из-за внедрённого средой HTTP-прокси. Это не записано как успешное прохождение команды. После восстановления прямого внутреннего трафика все 36 серверных и 3 облачных браузерных проверки выполнены на заново созданной базе. Обход описан в [CLOUD.md](CLOUD.md); отключения TLS-проверок нет.

Сборка сообщает предупреждения зависимостей о директиве `use client` и размере основного JS-чанка. Ошибок компиляции нет; дальнейшее разделение загрузки кода остаётся улучшением производительности.

**Не проверялись и не выполнялись:** развёртывание в рабочем Supabase, публичный HTTPS-домен/хостинг, отправка писем через внешний SMTP, нагрузочные испытания, воспроизведение стороннего YouTube в этой сети. Удалённый Supabase и хостинг ещё нужно настроить по [CLOUD.md](CLOUD.md), после чего проверить `/u/:username` из внешней сети. Локальные проверки не являются подтверждением готового интернет-деплоя.
