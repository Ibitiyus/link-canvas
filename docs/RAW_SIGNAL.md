# RAW SIGNAL v6 / Dirty Emo Punk

Редизайн сделан поверх актуального `main` (`ec88361`, PR #12). Production, указанный владельцем: https://zinpages.ru. В этой задаче production не развёртывался; Supabase, SMTP/Resend, секреты, Edge Functions и SQL-политики не менялись.

## Дизайн-система

`src/styles/tokens.css` задаёт чёрный `#07070A`, поверхности `#18121A` / `#261D29` / `#302333`, акцент `#FF2D91`, мягкий розовый `#FFB2D7`, красный опасных действий `#E0163B`, текст `#F6F0F5` / `#B8AFC0`, светлый `#FAF7F9`. У кнопок жёсткие рамки, без скруглений; primary с тёмным текстом, secondary с контрастной рамкой, icon buttons на графитовой поверхности. Есть hover/focus/active/disabled и существующие loading-состояния.

Использованы уже установленные Archivo Black, Roboto Condensed и IBM Plex Mono; новых runtime-зависимостей нет. Archivo используется в марке ZIN_, Roboto Condensed — в крупных кириллических заголовках и действиях, Plex Mono — в технических подписях/полях. Шрифты локальные из существующих @fontsource-пакетов.

`src/styles/raw-signal.css` подключается после существующих стилей и оформляет интерфейс приложения. Переиспользуются Brand, Field, NumberField, ColorField, PanelHeader и общие классы кнопок. Для пользовательских страниц не добавлялись глобальные фильтры, смена цветов, размера текста или transform. `.page-surface`, медиаконтент и геометрия композиции сохраняют авторские inline-настройки. Новая разметка сетки ограничена `.editor-surface`.

## UX

- Полностью новая структура главной: четыре строки «САЙТ НЕ / ОБЯЗАН / БЫТЬ / НОРМАЛЬНЫМ.», асимметрия, плакатная маркировка, две реальные CTA (`/editor`, `/explore`), работающая песочница, инструменты, ссылки на существующие стартовые композиции, финальный CTA и футер. Ссылки на шаблоны обозначены как шаблоны, а не вымышленные пользовательские публикации.
- Mobile landing проверен на 320/360/390/430 px; меню раскрывается кнопкой 44×44, фокус переходит в навигацию, Escape закрывает её и возвращает фокус.
- На desktop сохранены три области редактора. Выделены сохранение/публикация, вкладки, поля, слои, уведомления и опасные действия.
- На mobile внизу **ровно четыре вкладки**: Блоки / Слои / Свойства / Публикация. Они открывают sheet поверх части полотна; закрытие, свайп ручки, расширение и независимая прокрутка сохранены. Настройки страницы и масштаб доступны из «Свойств», масштаб также есть над полотном. Публикация использует существующий CloudBar и кабинет, а не отдельный новый процесс.
- У выбранного блока есть «Изменить / Двигать / Ещё». «Двигать» включает перемещение без удержания следующего касания для блока или группы, через существующую систему Pointer Events. Пока режим активен, кнопка отмечена и обычное панорамирование на выбранном объекте заменяется drag; повторное нажатие или смена выбора выключает режим. Обычное удержание, скролл и режим взаимодействия с медиа сохранены.
- Полоса контекстных действий резервирует место и до выбора: интерфейс не сдвигает объект между pointerdown/pointerup. «Ещё» даёт дублирование, слои, блокировку и удаление с подтверждением; расширенные групповые операции остаются в существующей панели выделения/слоях.
- Учитываются visualViewport, safe-area и клавиатура. При уменьшении доступной высоты sheet перерасчитывается, активное поле прокручивается в видимую область; Escape возвращает фокус на нижнюю вкладку, в том числе из настроек страницы/масштаба.
- Сетка: автоматические тёмные линии на светлом фоне, светлые на тёмном, контрастный дополнительный контур на изображениях; доступны ручные «Тёмные линии», «Светлые линии», «Скрыть сетку». Учитывается alpha фона. Это локальная настройка отображения, не поле проекта: JSON/облако/Undo не меняются. В предпросмотре и `/u/:username` сетки нет.

| Проверка | Результат |
| --- | --- |
| `npm run typecheck` | Пройдена |
| `npm test` | **172/172**, 22 файла |
| `npm run build` | Пройдена |
| Production Playwright, полный прогон | **128/128**, 7.4 минуты, Chromium, один worker, trace отключён |
| Финальные RAW SIGNAL tests | **11/11**, 21.7 секунды; включая дополнительно блок/группу без удержания, Undo, Escape из вложенной панели |
| `npm run test:e2e:cloud` | **7/7** на настоящем локальном Supabase, около минуты |

Полный прогон включает существующие сценарии перетаскивания/resize/поворота, группировки, слоёв, прозрачности фона, медиа/QR, импорта/экспорта, сохранения, восстановления, offline, шаблонов, Explore и масштабирования публичных страниц. Также прошли существующие проверки 100/200 блоков с CPU throttling. Облачные сценарии проверяют Auth/сессии, сохранение, публикацию на другом устройстве, конфликты, загрузку файлов, восстановление пароля через локальный Mailpit и добровольную галерею.

После полного прогона отдельно проверены последние уточнения: alpha-контраст фона (unit), фокус вложенных панелей и direct move группы (финальные RAW tests). Не заявляется проверка production SMTP/Resend, живого production-деплоя или физической iOS-клавиатуры: короткий viewport и touch проверялись Chromium/CDP. Safari/iOS стоит дополнительно проверить владельцу. Исходящие внешние YouTube/медиасервисы зависят от сети; тесты используют контролируемые медиа и локальные публикации.

В ранних итерациях тесты выявили: Escape в меню, сдвиг выбора при появлении контекстной полосы, доступность поля после уменьшения viewport и высоту верхней панели. Эти ошибки исправлены до финальных успешных прогонов. Предыдущие результаты не выдаются за финальные.

Повторение:

```sh
npm ci
npm run typecheck
npm test
VITE_SUPABASE_URL=http://127.0.0.1:54321 VITE_SUPABASE_ANON_KEY=zin-local-renderer-test npm run build
TEST_PRODUCTION=1 ZIN_CANVAS_E2E=1 npm run test:e2e -- --workers=1 --trace=off
npm run test:e2e:cloud
```

Для последней команды нужен запущенный локальный Supabase; wrapper запрещает production-адреса и создаёт/убирает только тестовые аккаунты. Для облачного Chromium при необходимости: `XDG_CONFIG_HOME=/tmp/link-canvas-browser/config XDG_CACHE_HOME=/tmp/link-canvas-browser/cache`.

## Проверка после merge / деплоя

1. Объединить PR обычным способом и дождаться production-деплоя Vercel на `zinpages.ru`. Для этого редизайна не нужно выполнять SQL или менять SMTP/ключи.
2. На 320/360/390/430 px проверить заголовок, меню, обе CTA, шаблоны и песочницу.
3. На телефоне добавить текст/изображение, выбрать касанием, изменить, открыть «Ещё», слои, закрепление, включить «Двигать», переместить, отменить; проверить resize, поворот и группу.
4. Проверить «Свойства → Настройки страницы» с клавиатурой, свайп/закрытие панели, вкладку публикации. На desktop проверить три панели.
5. Поставить белый, розовый, чёрный фон и фоновое изображение; проверить авто/ручную сетку и скрытие. Открыть preview и старую опубликованную страницу: авторские стили должны сохраниться, вспомогательная сетка отсутствовать.
6. Войти, сохранить в облако, опубликовать, открыть `/u/:username` без входа и Explore. Для доставки писем выполнить отдельный контрольный вход/восстановление с действующим Resend — настройки этого этапа не изменялись.
