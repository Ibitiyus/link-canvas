# Доставка статики собственного домена

На части сетей `zinpages.ru` отдаёт HTML, но загрузка JS/CSS зависает. При этом
тот же файл через `zin-pages.vercel.app` загружается полностью. Это наблюдение
не устанавливает причину сетевого сбоя (DPI, MTU и сбой провайдера не доказаны).

## Обход

`vercel.json` задаёт `ZIN_ASSET_ORIGIN=https://zin-pages.vercel.app` только для
команды сборки. `vite.config.mjs` использует его как `base` только при
`VERCEL_ENV=production`. Vite формирует абсолютные адреса JS, CSS, импортируемых
модулей, шрифтов и прочих ресурсов сборки. HTML и навигация остаются на домене
посетителя, как и localStorage, IndexedDB и сессия Supabase. Медиа авторов
продолжают использовать сохранённые в проекте адреса.

Это обход проблемной доставки статики, а не исправление сетевого маршрута.
Если начнёт зависать и сам HTML, данное изменение не обеспечит доступность.

Оба домена должны указывать на Production **одного проекта Vercel**: файлы
запрашиваются по хешам той же сборки. Не перенаправляйте Vercel alias обратно
на собственный домен. Preview-деплои и локальная разработка используют `/`,
чтобы не загружать файлы другой версии из production. Публичный origin статики
не содержит секретов; при смене проекта его нужно обновить в `vercel.json`.

## Проверка

После production-деплоя откройте `https://zinpages.ru` без кеша. В Network
документ должен приходить с `zinpages.ru`, а JS/CSS/шрифты — с
`zin-pages.vercel.app`. Проверьте главную, `/editor`, `/templates`, `/explore`
и свою опубликованную страницу. Адрес навигации должен остаться `zinpages.ru`.

Автоматическая проверка отдельного origin:

```sh
VERCEL_ENV=production ZIN_ASSET_ORIGIN=https://zin-pages.vercel.app npm run build
TEST_PRODUCTION=1 ZIN_TEST_ASSET_ORIGIN=https://zin-pages.vercel.app npm run test:e2e -- tests/asset-origin.spec.ts
```

Браузерные тесты обслуживают реальные файлы `dist` на отдельном origin через
перехват запросов, чтобы не зависеть от текущего production-деплоя. Проверяют
главную, редактор и динамическую загрузку шаблонов на 390 и 1440 px, загрузку
шрифтов/CSS/JS, отсутствие запросов к локальному `/assets/` и ошибок JavaScript.
Это не заменяет проверку доступности домена из сети пострадавшего пользователя.

Чтобы отменить обход, удалите установку `ZIN_ASSET_ORIGIN` из `buildCommand` в
`vercel.json`, оставив `npm run build`, и выполните новый production-деплой.
SQL, Supabase и DNS менять не требуется.
