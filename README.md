# ZIN

Визуальный редактор страниц на **React + TypeScript + Vite**. Локальный режим доступен без регистрации. Этап 3 добавляет Supabase Auth, приватные облачные черновики и независимую публикацию по `/u/:username`.

**Настройка аккаунтов, PostgreSQL, Storage, серверной функции и размещения в интернете: [docs/CLOUD.md](docs/CLOUD.md).** Без переменных Supabase редактор продолжает работать локально. Результаты проверок: [docs/STAGE3-VALIDATION.md](docs/STAGE3-VALIDATION.md).

## Запуск

Нужен **Node.js 24 LTS** (см. `.nvmrc`). Из текущего репозитория:

```sh
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev
```

Вне облачной среды можно использовать обычный `npm ci`, без параметра `--cache`. Dev-сервер использует порт **5173**. Открывайте `/editor` через адрес вашего dev-сервера. В облачной среде используйте существующий checkout `/workspace/link-canvas`: отдельный Git worktree не нужен.

Маршруты:

- `/` — главная страница и вход в редактор.
- `/editor` — библиотека блоков, полотно, слои и настройки.
- `/preview` — предпросмотр текущего черновика без сетки и управляющих элементов. Информационную полоску сверху можно скрыть.
- `/login`, `/register`, `/forgot-password`, `/reset-password` — аккаунт и восстановление доступа.
- `/dashboard` — облачный черновик, перенос локальной страницы, публикация и username.
- `/u/:username` — опубликованная страница для посетителей без входа.

## Как пользоваться

1. Добавьте блок из библиотеки слева. При первом запуске доступны четыре демонстрационных блока.
2. Выберите блок нажатием на него или в списке слоёв. Изменяйте содержимое и оформление в правой панели.
3. **Перемещение**: тяните ручку `⠿` в верхнем левом углу сеточного блока. На сенсорном экране ручки всегда видны. Во время движения показывается место назначения; положение фиксируется при отпускании. `Esc` отменяет незавершённое перемещение.
4. **Размер**: тяните нижний правый угол выбранного блока или задайте ширину и высоту в ячейках в настройках.
5. При пересечении перемещаемый/изменяемый блок получает приоритет. Остальные ищут свободное место в своей строке, затем ниже. Блоки не накладываются и не теряются. Новые строки добавляются автоматически.
6. Для **декора** используйте перетаскивание самого элемента. Он не занимает ячейки. Доступны X/Y, ширина, высота, поворот и z-index; кнопки выше/ниже во вкладке «Слои» меняют порядок декора. Координаты и размеры задаются в логических пикселях; весь декор масштабируется вместе с полотном по обеим осям. Новый декор имеет поворот **0°**; X/Y могут быть отрицательными и выходить за любую границу сетки. Вокруг страницы появляется прокручиваемое пространство с учётом поворота элемента. Старые сохранённые повороты не сбрасываются.
7. Вкладка «Страница» меняет фон, фоновое изображение, 3/4/5 колонок, расстояния, максимальную ширину и шрифт. Есть три готовых варианта оформления.
8. «Предпросмотр» сохраняет проект и открывает его без панелей, выделения и ручек. Ссылки открываются в новой вкладке, видео доступны для воспроизведения.

Поддерживаются:

- **Ссылка**: HTTP(S) URL, текст кнопки, необязательное изображение.
- **Текст**: многострочный текст, выбор шрифта и установка собственных файлов, размер, цвет, выравнивание и жирное начертание.
- **Изображение / GIF**: HTTP(S) URL или файл с устройства, `cover` или `contain`. GIF сохраняет анимацию.
- **Видео**: YouTube (`watch`, `youtu.be`, `shorts`, `embed`, `live`) или прямые `.mp4`, `.m4v`, `.webm`, `.ogv`, `.ogg`, `.mov` URL, включая query-параметры. Кнопка «Загрузить с устройства» принимает видеофайл; браузер проверяет его метаданные и поддержку кодека до замены содержимого блока. YouTube ID проверяется; iframe создаётся только на `www.youtube-nocookie.com`. Плеер в редакторе защищён от случайного взаимодействия, воспроизведение доступно в предпросмотре.
- **Музыка**: аудиофайл с устройства (MP3, WAV, OGG/Opus, M4A, AAC, FLAC, WebM) или прямая HTTP(S) ссылка на аудио/поток. Оформленный проигрыватель работает в редакторе и предпросмотре: play/pause, перемотка, время и громкость, необязательная обложка. Название трека, фон, цвет текста, рамка и скругление меняются в настройках. Автозапуска нет; ссылки на страницы Spotify/YouTube/SoundCloud не являются прямыми аудиоссылками.
- **QR-код**: введите HTTP(S) ссылку в поле «Ссылка для QR-кода». Код генерируется локально и сразу обновляется. В предпросмотре нажатие открывает ту же ссылку в новой вкладке; в редакторе нажатие выбирает блок. Можно менять размер, фон, цвет кода, рамку и скругление. Для сканирования сохраняйте высокий контраст; очень длинный адрес может потребовать сокращения. Ссылка и оформление входят в автосохранение и JSON-копию.
- **Декор**: emoji/символ либо изображение поверх сетки.

Для всех блоков доступны название, фон, цвет текста, скругление, прозрачность и рамка. Нерабочие изображения и неподдерживаемые видео показывают сообщение вместо сломанного содержимого.

## Сохранение и резервные копии

Проект автоматически сохраняется после изменений с задержкой **350 мс**, а также при уходе со страницы. Индикатор показывает сохранение, успех или ошибку; нажатие на индикатор сохраняет немедленно.

Ключ localStorage: `link-canvas.project.v1`. Структура метаданных: `{ version: 1, page: {...}, blocks: [...], customFonts?: [...] }`. Сами загруженные файлы находятся в **IndexedDB** `link-canvas.files.v1`, object store `files`; поля проекта содержат стабильные ссылки `asset:<id>`. `blob:` URL создаются только для показа и освобождаются после использования. Сохраняются содержимое, типы, уникальные ID, сеточные и свободные координаты, размеры, оформление, z-index и настройки страницы.

- После обновления страницы проект и файлы восстанавливаются в том же браузере и на том же origin.
- Экспорт JSON включает все используемые файлы в поле `assets` (base64), а не только ссылки на IndexedDB. Такой файл можно перенести на другое устройство. Импорт проверяет структуру, версию, типы и уникальность ID, нормализует сеточную геометрию и спрашивает подтверждение замены. Файлы импортируются одной транзакцией с новыми ID, чтобы сохранить работу отмены. Старые проекты версии 1 со встроенными изображениями/шрифтами также читаются.
- Повреждённое сохранение не перезаписывается автоматически: показывается ошибка. Первое явное изменение или ручное сохранение заменит его текущим проектом.
- **Ограничения 10 МБ и 1 МБ со стороны приложения сняты**, в том числе для импорта JSON. Файлы не проходят через localStorage и не уменьшаются автоматически. Доступное место всё равно ограничено квотой браузера и диском, а декодирование и JSON-экспорт — памятью устройства. При отказе записи файла показывается ошибка, прежний файл в блоке не заменяется. Для полного экспорта нужны доступные исходные файлы в IndexedDB.
- Удаление блока/файла из страницы не удаляет его бинарные данные немедленно: они нужны для отмены. Очистка данных сайта удалит и проект, и файлы; предварительно экспортируйте JSON. Медиатека с управлением занятым местом остаётся следующим этапом.
- Отмена и повтор хранят последние 60 изменений в памяти текущей вкладки. Сброс спрашивает подтверждение и тоже отменяется. После перезагрузки история действий начинается заново.

Горячие клавиши вне полей ввода: `Ctrl/⌘ Z`, `Ctrl/⌘ Shift Z` или `Ctrl/⌘ Y`, `Ctrl/⌘ D` (дублирование), `Delete/Backspace` (удаление), `Esc` (отмена жеста / снятие выбора).

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

- Vitest: размещение и перераспределение, пересечения, размеры и границы, изменение числа колонок, декор, сериализация, обработка повреждений/квоты, безопасные медиа URL, отмена/повтор.
- Playwright: переходы между страницами; настоящее перетаскивание и изменение размеров мышью; отсутствие пересечений; свойства и восстановление после reload; слои; JSON import/export; подтверждение сброса; обработка ошибок localStorage; загрузка изображений/GIF и воспроизведение WebM; безопасный YouTube iframe; открытие ссылки; мобильная компоновка и перемещение касанием; горячие клавиши и отмена жеста.

Playwright запускает собственный сервер на порту **5180**. Используется Chromium из `/usr/bin/chromium`, если он установлен, иначе браузер Playwright. При необходимости установите его командой `npx playwright install chromium`. Можно явно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

В облачной среде с домашним каталогом только для чтения:

```sh
XDG_CONFIG_HOME=/tmp/link-canvas-browser/config \
XDG_CACHE_HOME=/tmp/link-canvas-browser/cache \
npm run test:e2e
```

Те же браузерные сценарии на production-сборке:

```sh
npm run build
TEST_PRODUCTION=1 npm run test:e2e
```

В облачной среде добавьте те же `XDG_*` из команды выше. Медиа-тесты используют небольшие GIF/WebM из `tests/fixtures` и перехват HTTP-запросов; проверяют реальную загрузку и воспроизведение WebM, но не доступность сторонних сервисов. Реальный запрос к YouTube и внешнему примеру MP4 из этой облачной среды получил сетевой `403`. Реальное воспроизведение YouTube здесь не подтверждено: ему нужен доступ к YouTube и его медиадоменам. Доступность любых внешних изображений/видео зависит от сети, владельца файла, кодеков и разрешения на встраивание.

Для ручного просмотра production-сборки:

```sh
npm run preview
```

Порт **4173**, файлы в `dist/`. Vite сообщает предупреждения зависимостей о директиве `use client`; для этого клиентского SPA они не препятствуют сборке. На статическом хостинге потребуется SPA fallback на `index.html`, чтобы прямые переходы на `/editor`, `/dashboard`, auth-маршруты и `/u/:username` работали.

## Структура

```text
src/
  App.tsx               маршруты
  model/                типы, демо, алгоритмы сетки, декор, медиа, JSON/storage
  state/                состояние проекта, история, локальное автосохранение
  auth/                 сессия, username и безопасные возвратные маршруты
  cloud/                Supabase, загрузки, последовательная синхронизация и миграция
  components/           полотно, отображение блоков, библиотека, панели, поля
  pages/                главная, редактор, предпросмотр, аккаунт, кабинет, публичная страница
  style.css             точка входа стилей
  styles/               токены, UI, главная, полотно и предпросмотр
tests/                  браузерные сценарии и медиа-фикстуры
docs/                   описание дизайна и скриншоты
scripts/                запуск Supabase, интеграционные проверки, съёмка интерфейса
supabase/               SQL-миграция, RLS/Storage policies и Edge Function
```

Используются React Router, Lucide React, Vitest и Playwright. Для облака добавлены @supabase/supabase-js, tus-js-client и локальный Supabase CLI (dev dependency). Archivo Black и IBM Plex Mono подключены локально через Fontsource. Перетаскивание реализовано через Pointer Events (мышь/касание); состояние — через React Context + reducer. Дополнительные библиотеки сетки и состояния для этого этапа не требуются.

## Текущие ограничения

- Один локальный проект на origin браузера и один облачный проект на аккаунт, до 200 блоков. Локальный объём ограничен возможностями браузера/устройства; облачные лимиты настраиваются отдельно, по умолчанию 50 МиБ на файл. Резервная копия особенно важна перед очисткой данных браузера или сменой устройства.
- `/preview` показывает текущий черновик; для публичного адреса используйте публикацию в кабинете. Облачное сохранение синхронизирует аккаунт между устройствами, конфликты требуют явного выбора версии. Совместное редактирование в реальном времени пока не реализовано.
- Пользовательское полотно имеет фиксированную логическую ширину (`page.maxWidth`), строки по 112 логических px и единую композицию на всех устройствах. На узких экранах масштабируется всё полотно; доступны «+», «−» и «По ширине». Формат проекта и сохранённые координаты не меняются. Подробнее: [docs/CANVAS-SCALING.md](docs/CANVAS-SCALING.md).
- Изображения, видео и музыку можно задавать URL или загружать с устройства. При подключённом Supabase файлы загружаются в приватный Storage и отдельно копируются при публикации. Медиатеки и rich text пока нет.
- Живые процессы не сохраняются в снимке облачной среды: после восстановления запускайте `npm run dev` заново.

Следующий полезный этап: шаблоны страниц, группировка изменений текста в истории и медиатека. Аккаунты, облачная база и публикация реализованы в этапе 3; настройка рабочего развёртывания описана в docs/CLOUD.md.

## Дизайн: independent internet

Интерфейс полностью обновлён в эстетике Y2K / punk / cyber grunge: чёрные поверхности, красные и розовые акценты, плакатные заголовки, прямоугольные панели и техническая сетка. Общие токены — `src/styles/tokens.css`. Подробности и скриншоты: [docs/DESIGN.md](docs/DESIGN.md).

На главной работает отдельная песочница: в примере можно перемещать блоки и менять размеры, переключаться в просмотр, открывать ссылки и воспроизводить локальное демонстрационное видео. Изменения песочницы не затрагивают ваш проект.

На экранах до 1050 px библиотека, полотно и настройки переключаются кнопками над рабочей областью. После добавления блока открываются его свойства. Чтобы двигать его касанием, вернитесь во вкладку «Полотно» и тяните ручку.

Существующие проекты не перекрашиваются. CSS интерфейса отделён от отображения содержимого; белый фон, зелёные кнопки, собственные шрифты, скругления и другие сохранённые настройки продолжают работать. Новое оформление демонстрационных блоков применяется только при первом запуске или явном сбросе страницы.

Для повторного создания скриншотов запустите приложение, затем в другом терминале:

```sh
npm run capture:design
```

По умолчанию используется порт 5173, другой адрес можно передать через `BASE_URL`. В облачной среде примените те же `XDG_*`, что и для Playwright выше. Изображения сохраняются в `docs/screenshots`. Режим reduced motion делает кадры стабильными.

На Windows для установки в локальной папке проекта выполните `npm ci --include=dev`, затем `npm run dev`. Зависимости Vite не нужно устанавливать глобально.

## Изображения и шрифты с устройства

Для блока «Изображение», GIF, картинки в ссылке, музыкальной обложки или декора и фонового изображения страницы доступна кнопка **«Загрузить с устройства»**. У прямого видеофайла также можно загрузить обложку. URL остаётся альтернативой; удалить выбранное изображение можно кнопкой рядом с загрузкой.

Поддерживаются **PNG, JPEG, WebP и GIF** без установленного приложением ограничения размера. Оригинальные байты и разрешение сохраняются; изображения не уменьшаются и не перекодируются, GIF сохраняет анимацию. SVG, HEIC и AVIF с устройства пока не поддерживаются; ссылки на внешние изображения работают как раньше.

В настройках **текстового блока** появился список «Шрифт блока». Вариант «Как у страницы» наследует общий шрифт, остальные варианты меняют только выбранный блок. Archivo Black и IBM Plex Mono поставляются с приложением; доступность Arial, Verdana и других системных шрифтов зависит от устройства.

**«Установить шрифт»** принимает WOFF2, WOFF, TTF и OTF без ограничения размера со стороны приложения. Можно установить до 8 шрифтов на проект, выбирать их для разных текстовых блоков и удалять. Файл проверяется декодером браузера. Наличие кириллицы зависит от самого файла. Установка относится к текущему проекту, а не к операционной системе. Удаление шрифта возвращает использовавшие его блоки к шрифту страницы; действие можно отменить.

Изображения, медиа и шрифты с устройства хранятся в IndexedDB. Установленные шрифты перечислены в необязательном поле `customFonts`, выбор для текстового блока — в `fontFamily`. Файлы входят в полный JSON-экспорт. Без аккаунта это локальное хранение; после входа и сохранения файлы передаются в приватный Storage. Исходный файл должен поддерживаться браузером.

## Открытие с другого устройства в локальной сети

`npm run dev` уже слушает `0.0.0.0:5173`. После запуска на компьютере можно открыть `http://<локальный-IP-компьютера>:5173/` с другого устройства в той же сети, например `http://192.168.0.224:5173/`. Этот частный адрес не является публичным адресом в интернете.

Исправлена причина пустого/чёрного экрана при таком HTTP-доступе: `crypto.randomUUID()` доступен не во всех небезопасных контекстах. Генератор ID использует совместимый путь через `getRandomValues`, а при отсутствии Web Crypto — локальный fallback. Он применяется к блокам, дубликатам и загружаемым шрифтам. При неожиданной ошибке рендеринга показываются повторная загрузка и экспорт сохранённого JSON, без автоматического удаления данных.

`localhost`, локальный IP и другой порт — **разные origin**. Сохранение одного адреса не появляется автоматически на другом адресе или устройстве. Для переноса используйте JSON с файлами. Для доступа из внешнего интернета нужен отдельный HTTPS-хостинг production-сборки; публикация Git-репозитория сама по себе сайт не запускает.

Проверки включают TypeScript, production build, модульные тесты сетки/геометрии/сохранения и браузерные сценарии. Отдельные сценарии загружают видео, WAV и PNG **больше 10 МБ**, проверяют реальное воспроизведение, перемотку/громкость, сохранение оригинальных байтов, reload, перенос JSON с файлами после очистки IndexedDB, ошибки квоты и повреждённые файлы. Внешние медиа в автоматических тестах подменяются контролируемыми ответами; поддержка сторонних сервисов этим не подтверждается.

## Русский интерфейс и название ZIN

Приложение называется **ZIN**. Главная страница, редактор, предпросмотр, ошибки, подсказки и демонстрационные постеры переведены на русский. Названия форматов и сторонних сервисов сохраняются; пользовательские тексты не переводятся автоматически. Плакатные заголовки используют Roboto Condensed с локально поставляемой кириллицей.

Старые проекты Link Canvas открываются без миграции: ключ `link-canvas.project.v1`, хранилище `link-canvas.files.v1` и структура проекта сохранены ради совместимости. Новые резервные копии скачиваются как `zin.json`, аварийные — как `zin-recovery.json`; старые JSON-файлы также импортируются.
